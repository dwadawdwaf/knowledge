## ISS-001：持续回收过期任务

- **位置**：`backend/knowledge/worker/loop.py`，`run_forever`。
- **现状**：只在启动时回收过期租约，循环中只领取 queued 任务。
- **触发与影响**：Worker 崩溃后在原租约到期前重启，启动巡检跳过该任务；之后即使租约过期，也没有再次巡检，任务可能一直 running。
- **修复方向**：在循环中定期执行回收，保持有限重试；达到最大尝试次数的任务不得无限重新入队。同步修订设计中仅启动巡检的描述。
- **验收**：覆盖租约到期前重启、运行中租约过期、多 Worker 同时巡检和最大重试次数；不依赖人工重启完成恢复。

## ISS-002：固定任务对应的构建目标

- **位置**：`backend/knowledge/services/document.py`，`upload` / `add_version`；`backend/knowledge/services/ingest.py`，`run`。
- **现状**：任务只关联文档 ID，执行时读取文档当前的 `pending_build_id` 与 `generation`。
- **触发与影响**：连续提交 v1、v2 时，v1 任务可能处理 v2；多个任务可能处理同一 build，较慢任务可能删除并重写已发布分块。
- **修复方向**：任务创建时固定目标 build 与 generation；执行时验证任务目标及构建状态，禁止修改 ready build。涉及任务表或接口语义的变化，先更新设计并追加决策记录，再新增迁移。
- **验收**：连续提交两个版本、两个 Worker 交错执行、旧任务延迟完成时，任务与 build 始终对应；ready build 的分块 ID 和内容不被重写。

## ISS-003：将租约校验与写入组成原子操作

- **位置**：`backend/knowledge/services/ingest.py`，`_holds_lease`、写分块阶段及 `publish`；`backend/knowledge/repositories/jobs.py`，租约相关操作。
- **现状**：只检查 token 和 running 状态，不检查租约截止时间；查询校验与后续写入之间没有任务行锁保护。
- **触发与影响**：校验通过后发生租约回收，旧 Worker 仍可能写入；已过期但尚未回收的租约也可能通过校验。
- **修复方向**：在同一短事务内校验有效租约并完成受保护写入，采用一致的锁顺序或条件更新；事务持锁期间不调用模型、解析器等外部依赖。
- **验收**：过期 token、被接管 token、取消任务均不能写入或发布；用双数据库会话覆盖“校验后发生接管”的交错场景。

## ISS-004：原子提交发布状态与任务结果

- **位置**：`backend/knowledge/services/ingest.py`，`publish` 末尾。
- **现状**：先提交发布指针与 build 状态，再通过独立事务将任务置为 succeeded。
- **触发与影响**：两次提交之间崩溃，会产生内容已发布但任务仍 running 的状态；恢复时又可能因 pending 指针为空而标记 cancelled。
- **修复方向**：文档指针切换、新 build 就绪、旧 build 退役、任务成功在同一事务提交；事务提交权由用例层统一管理。
- **验收**：在提交边界注入失败，结果只能是全部回滚或全部成功，不出现已发布但任务未成功的中间结果。

## ISS-005：隔离内部异常与对外错误

- **位置**：`backend/knowledge/worker/loop.py`，通用异常处理及 `_handle_failure`；`backend/knowledge/api/v1/routers/jobs.py`，`last_error` 返回；文档详情也返回该字段。
- **现状**：异常类型及原始异常正文直接写入 `last_error`，随后原样返回客户端。
- **触发与影响**：数据库异常可能包含 SQL、参数或片段内容；文件异常可能包含绝对路径。
- **修复方向**：对外使用白名单错误码和固定说明；内部诊断独立处理并脱敏，不能将完整异常参数转移到日志中。保留安全的关联标识用于排查。
- **验收**：注入包含文件路径、SQL、测试令牌和自制片段正文的异常，确认任务接口、文档详情及日志均不泄露这些内容，同时错误仍可归因。

## ISS-006：校验查询与索引的向量模型兼容性

- **位置**：`backend/knowledge/services/retrieval.py`，`search`；`backend/knowledge/repositories/chunks.py`，语义召回条件。
- **现状**：查询使用当前 embedder，召回未校验 build 的模型标识。
- **触发与影响**：切换成相同维度的另一模型后，维度校验无法发现问题，不兼容向量会被静默比较。
- **修复方向**：明确并校验模型兼容标识；不兼容时阻断语义检索并要求重建。如允许退回关键词模式，须先明确设计语义并返回降级说明，不能静默回退。
- **验收**：相同维度不同模型不得混检；同模型正常检索；重建完成后恢复；降级模式如启用，响应包含明确标识。

## ISS-007：限制解析资源与运行时间

- **位置**：`backend/knowledge/adapters/parser.py`，`DocxParser.parse` / `PdfParser.parse`；Worker 解析执行边界。
- **现状**：直接调用解析库，没有 DOCX 解压总量、条目数限制，也没有可强制终止的解析时限。
- **触发与影响**：上传大小限制不能约束解压后资源占用；复杂或异常文件可能耗尽内存或长时间占用 Worker，持续心跳不能解决解析卡死。
- **修复方向**：增加压缩包预检查；解析放入可终止的独立进程，设置时间与资源上限；超限返回明确、安全的错误。
- **验收**：使用小型自制样本和受控阻塞解析器覆盖条目数、解压量、时间限制；超限后进程被回收，后续任务仍能执行。不得在共享环境运行真实资源耗尽样本。

## ISS-008：统一畸形令牌错误处理

- **位置**：`backend/knowledge/security.py`，`verify_token`。
- **现状**：Base64 解码等异常未统一映射为 `AuthenticationFailed`。
- **已验证**：本地调用 `verify_token("a.x", Settings(_env_file=None))` 触发未归一化的解码异常；按当前 HTTP 异常映射会进入通用 500。HTTP 级回归测试仍需补充。
- **修复方向**：对编码、JSON、载荷结构及字段类型进行有界校验，失败统一返回认证失败，不暴露内部异常。
- **验收**：非法编码、非法签名、异常 JSON 结构、错误字段类型、过期令牌返回 401；合法令牌保持正常。
