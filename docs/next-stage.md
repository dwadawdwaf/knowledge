# 当前进度与下一阶段开发计划

_检查日期：2026-10-26；范围：本仓库的知识检索与智能问答后端。_

> 这是开发计划，不修改接口或权限契约。涉及新增接口、状态语义、身份映射的条目，须先评审并更新 `design.md` / `decisions.md`，再实施。

## 1. 当前判断

**核心后端原型已实现，并通过一轮工程加固；下一目标是形成可供主系统联调的后端候选版，而不是立即扩展 Agent 平台。**

不能据此认定整个二创项目完成了多少百分比：仓库未提供模型训练、公文处理、信息服务、样机等其他分支的完整实现和验收证据。

### 必须分清的三件事

1. **94 项回归通过**证明当前测试所覆盖的行为，不证明真实模型效果或生产可用性。
2. **8 项审计问题关闭**见 `docs/issues.md`，不代表根目录 `issues.md` 中的产品、评测和接入事项全部关闭。两份文件编号有重叠，引用时必须带路径。
3. 根目录 `issues.md` 属历史记录，其中“仅有 0001 迁移”“没有失败路径覆盖”等观察已被后续工作部分或全部改变；历史吞吐与延迟也不能直接作为解析隔离改造后的基线。

## 2. 下一阶段目标与边界

目标：主系统调用方能够按文档启动服务，以已约定的身份和知识范围，稳定完成上传、处理、检索、问答、引用、更新、失败恢复及删除。

保留现有技术基线，不增加新的任务中间件或向量数据库。优先复用已有 API、任务表、Worker、适配器和测试资料。

以下继续不做：前端富预览、账号平台、多轮推理、OCR、网页连接器、共享库、模型训练、工作流平台。MCP 仅在接入方确实需要且决策确认后推进。

## 3. 开发顺序

### N1：先把后端变成可复验的联调对象

**优先级：最高；不依赖甲方资料或真实模型。**

- 将现有演示流程改造成自动化 HTTP E2E：带令牌建库、multipart 上传、轮询、检索、问答、引用读取、版本替换和删除。
- API 和独立 Worker 使用同一隔离数据库与文件目录；不要用测试中直接调用 `process_next` 代替全部进程级验证。
- 补实际 Worker 终止与重启场景，与当前手工修改租约的故障注入测试互补。
- 补模型适配器异常响应契约：超时、限流/服务错误、空结果、非法 JSON、错误字段类型、向量返回数量/顺序异常；服务故障不得映射为 no_evidence。
- 固定 Python 与依赖版本，建立与本地相同的 lint、类型、隔离数据库回归流程；优先复用 `scripts/test_isolated.py`，不能因集成测试被跳过就宣布流水线通过。
- 梳理联调所需的配置、错误码、任务终态和引用读取步骤；只修影响这些链路的分层问题，不开展全仓库重构。

**交付物**：E2E 测试、可复现依赖、自动检查配置、调用示例和更新后的运行手册。

**退出条件**：干净环境按同一份说明可启动；正常链路、跨用户拒绝、删除阻断、Worker 重启和上游失败均可自动验证。

### N2：补齐失败后的人工恢复与同模型重建

**实施状态：已按用户确认的契约完成，验证记录见 §10；以下保留立项背景与退出条件。**

**优先级：高；先评审设计，再实现。**

立项时 Worker 能自动重试，但任务达到上限后缺少明确的业务恢复入口。相同字节重新上传会去重返回，不应把“重新上传”当作可靠的失败恢复方案。原有 reindex 枚举和执行分支在本批复用于公开重建用例。

- 建议以一个受授权的“重建现有版本”用例覆盖可恢复失败和主动重建，避免先新增多个近似接口。
- 复用现有 version / build / job，不复制原文件，不创建无意义的新版本；新建 build，不修改 ready 构建。
- 明确目标版本、generation 冲突、已有任务时的重复请求、失败构建的展示，以及删除状态下的拒绝行为。
- 首次实现限定于同一向量配置；不同模型的物理索引迁移继续离线评估，不承诺在线混写。

**交付物**：经确认的契约、服务用例、薄 REST 入口、权限及并发回归。

**退出条件**：一个超过自动重试次数的任务，在故障排除后可通过公开业务入口恢复；重建期间旧发布内容继续服务；重复操作、冲突、越权与已删除资源均有确定结果。

### N3：验证“答得对”，而不只验证“有引用”

**实施状态：固定标注、评测工具与首次授权真实诊断已完成；效果验收未通过。见 §11 与 n3-evaluation.md。**

**优先级：高；本地评测准备可立即进行，真实模型调用须另行确认授权。**

- 使用现有自制资料补齐业务型问题：精确事实、语义改写、跨段信息、文号/专名、库外问题、同主题无答案、过期版本、文档内指令干扰。
- 为每个问题标注能否回答、必要事实及支持片段；将评测资料与日常回归隔离，避免慢评测污染快速测试。
- 分别记录检索命中、首位排序、答案事实正确性、原文支持程度、拒答、耗时和调用成本。不要只给单一总分。
- 根目录问题清单和当前评测代码已记录“同主题无答案”的风险；这类用例不能长期只打印命中数而不验收答案行为。
- 先比较 keyword / semantic / hybrid 的固定数据结果，再决定是否试验成熟重排组件或分词器。相似度分布重叠并不能单独证明替换检索引擎有效，重排也不自动解决可回答性。
- 真实生成模型进入验收前，评审“部分段落无证据”和“检索有结果但证据无法回答”的处置语义；当前 design §6.2 的规则不能被实现自行改写。
- 经授权后，用明确版本和配置的 embedding / generator 重跑，保存脱敏的结果摘要；历史 bge-m3 指标不能替代新版本实测。

**交付物**：固定问题集与标注、离线评测入口、真实模型评测摘要、失败案例分类。

**退出条件**：先确认业务验收口径，再按冻结问题集逐项验证；关键错误答案及伪证据案例有明确处置，未达标的能力如实标记限制。未跑真实生成模型，不宣布问答效果通过。

### N4：主系统联调与受控试点

**依赖：N1、N2；资料接入另需安全决策完成；正式效果验收依赖 N3。**

- 对接主系统身份验证器，不在开发令牌桩上持续叠加条件；确认单租户/多租户及主体标识的实际语义。
- 确认知识库范围由谁提供、引用如何呈现、任务如何轮询、错误如何提示；优先 REST，不要求先有前端富预览。
- 接入资料前明确资料分级、模型是否允许外发、审计、保留和删除、配额与限流；这些不是“有空再做”的上线优化。
- 按确认的部署环境准备启动、迁移、健康检查、备份恢复与日志采集，复用主系统已有能力，避免重复建设。
- 甲方数据未就绪时继续使用自制样本联调，不把仿真验收称作甲方验收。

**交付物**：身份与接口对接说明、部署配置、脱敏验收记录、已知限制清单。

**退出条件**：调用方可独立复现流程；真实资料接入的前置条件全部确认；出现故障有恢复路径。

### N5：按需完成 QwenPaw 接入

仅在负责人确认 decisions 0008 且存在明确调用需求后启动。按 `design.md` §9 实现 MCP 协议、Skill 包和契约测试，复用 services，不 fork 宿主、不复制业务逻辑、不将记忆作为证据。

该项可以晚于 REST 联调，不应阻塞无 Agent 宿主依赖的核心交付。

## 10. N2 同模型重建与人工恢复（2026-10-26）

**已按用户确认契约完成。** 契约只在 design §7.1 定义，决策依据见 decisions 0012，
调用顺序与失败处置见 runbook §11。本批没有增加表、迁移、依赖或运行组件。

- 新增受授权的重建用例与薄 REST 入口，严格校验请求字段；仅处理最新上传版本，复用原件、版本和原构建配置。
- 文档锁下刷新对象并比较 generation，创建新 build / reindex job。两路并发相同请求只接受一路，另一路返回冲突，不新增幂等表。
- 重建期间与重建失败后均保留旧发布内容；成功后由既有 Worker 和发布事务切换指针。原片段保持不变，历史失败任务保持失败。
