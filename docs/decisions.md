## 0020 显式可选DeepDoc与MinerU（2026-10-30）

决定：用户批准所有已支持文档均可选基础、DeepDoc、MinerU，选择冻结到新build，普通重建不换策略，去重返回已有方案。
为兼容旧build，DeepDoc新增v2原生文档路径，v1保持原样。纯文本直接读取并明示，不伪装OCR。
MinerU复用本机4.1同步文件API及ZIP结构输出，不在主环境装SDK或搬平台，不新增业务表，不重启已撤销的聚合/规划方案。
理由：同一上传与发布链路复用成熟解析器，避免重复任务/引用体系；保留真实位置及精度降级。
被否：按格式自动切换而不提示、失败回退、篡改ready构建、重传绕过去重、接受第三方返回URL或云端上传、未授权下载模型。
重审：跨策略重建、远程部署、额外格式、精确几何及复杂表格语义另评审；真实模型效果未验收不能当交付指标。

## 0021 本机解析部署与可诊断失败（2026-10-30）

决定：用户批准D盘独立部署MinerU 4.1.2和basic/ONNX模型；后续默认仅本地模型，下载须显式选择。
DeepDoc新镜像标签v2，保留旧镜像；镜像站不可达时允许从已有可信边车制作离线代码更新层。
真实启动器可在内存复用本项目正在运行容器的令牌，不覆盖显式配置、不查询其他容器、不落盘。
v2图片版面全空时复用同版OCR并明确告警，v1不改；服务/配置错误保留白名单提示，不改错误码或自动切换解析器。
理由：修复服务未部署、旧镜像与令牌未传入造成的假性“文件损坏”；复用已下载组件，降低部署重复成本。
被否：关闭鉴权、写盘共享令牌、静默更换策略、修改ready内容、取消系统端口保留或覆盖主环境依赖。
重审：跨机、跨策略重建、生产身份/密钥管理或更高解析tier需求出现时另评审。

## 0022 持久基础评测与全局入口（2026-10-30）

决定：按用户要求备份清空当前本机业务库，换成版本化自制资料；固定多维度问题集，对比现有召回方案，先测基线不改算法。
全局检索测试改为只读评测过程/结果，手动检索下沉知识库页签并固定范围；不增加评测业务表或付费执行API。
过程/结果复用独立报告库原件与新版本，实际问答复用会话；标注报告不参与被测检索范围。
理由：复用既有授权、文件、发布与引用能力，先定位失败环节，避免把复杂评测平台当作检索优化。
被否：无备份直接清空、混入真实资料/网上未核对内容、浏览器自动重跑模型、把桩结果或词面覆盖称作真实准确率。
重审：需要多人共享实验、任务调度或大规模评测时再设计专门持久模型；当前容量与效果仅报告实测值。

## 0023 公开长文档第二轮实验（2026-10-30）

决定：用户明确批准六份已下载官方公开资料的相关片段进入现有deepseek-flash，最多240次检索/问答，48题开发/留出各24。
这是默认不外发真实资料规则的本次限定例外，不扩大到甲方/私人资料或其他模型；原件、真实片段和题目不进代码提交或测试夹具。
复用已有实验引擎、资料发布、报告原件与会话存档，保留第一轮并增加只读轮次/划分选择，不增加业务表或批量调用API。
理由：长文本和真实格式压力应与基础自制集分开，先固定现有算法/阈值取基线，再判断优化，不混淆资料变化与算法改善。
被否：清空第一轮、静默增预算、重复跑到好看、把公开资料视为可任意再分发、边跑边改题或调整阈值。
重审：需要新语料、不同模型服务、预算追加、算法对照或文档级独立盲测时另确认。

## 0024 PDF默认MinerU及实验设置变更（2026-10-30）

非PDF默认不变；显式选择优先，去重/重试/重建不切换已有策略；服务失败不回退基础解析。

理由：使日常PDF处理和用户指定的实验设置一致，同时不改写已发布构建或伪造同条件对照。
被否：重启即重新解析旧文档、只改下拉框但后端仍用基础解析、以删除失败记录掩盖入库边界。
重审：MinerU长文档容量/超时不满足时，先报告实测阻塞，不截页、不扩大预算或静默更换策略。

## 0025 无效字符修复及第二轮入库恢复（2026-11-01）

决定：用户批准MinerU正文NUL等长替换为U+FFFD并告警，保留原件、旧build及已发布内容；不改金标。
统一重启同库工作台/Worker，使用本轮已显式配置的128MiB输出预算及上游8页处理窗口，不关闭识别功能。

理由：只读参数查询已复现驱动拒绝NUL，另发现旧16MiB Worker竞争领取任务；先修复工程阻塞再计检索质量。
被否：删字符不告警、改写旧片段、删除失败记录或启动标记、跳过失败资料、重复已完成问答、追加240次预算。

## 0026 移除DeepDoc与Docker依赖（2026-11-06）

决定：按用户要求移除DeepDoc解析与容器边车；删除`deploy/deepdoc`、`backend/deepdoc_sidecar`及DeepDoc/Docker专属启动脚本，一键启动不再检查或拉起Docker Desktop。保留基础解析与MinerU，`parser_profile`只接受`legacy-v1`、`mineru-api4.1-v1`；历史DeepDoc构建只读保留，不新增、不重建。

重审：确需OCR/版面质量对照且MinerU不满足时另立方案，不恢复一键启动的Docker依赖。

## 0033 原生 OpenSearch 承接 RAGFlow 搜索（2026-11-11）

用户要求全面参考 RAGFlow 搜索策略，并允许 PostgreSQL 或 OpenSearch。为解决 PostgreSQL 逐候选 SQL 评分的秒级时延，更新0032的搜索引擎边界：保留 PostgreSQL 为业务、授权、版本、正文、向量与引用的权威存储；增加可配置的 OpenSearch 原生查询路径。PostgreSQL 路径供显式兼容回退，原生服务失败不自动降级。

参考固定 RAGFlow v0.24.0 的查询表达式、字段映射、ES召回及有限候选重排：原生 `query_string`、标题与重要词脚本相似度、正文BM25、文本过滤kNN、按页面大小确定候选窗口及词项/余弦最终评分。OpenSearch kNN DSL 与上游 ES 不同，采用 Lucene filtered kNN；不声称底层引擎及候选结果逐位一致。上游ES适配器实际将文本boost设为0.05，向量boost沿用默认1，而非直接把名义融合参数0.05/0.95同时乘两路；按实际适配器复用。

索引仅为可重建派生数据，先按SQL授权及当前build限定两路候选，再回源复核。上传在发布前同步不可变build并刷新、最后写完成标记，失败不替换旧版本；租约和generation仍在最终发布时复核。删除提交即时由SQL阻断，物理清理另行删除搜索数据。旧向量直接回填，不重分块或重新向量化。

保留本项目的最小功能边界：无图谱、多跳、标签/PageRank和问答增强字段生成；未配置外部重排模型时使用上游标准词项/向量相关度。指定资料无命中仍放宽条件补召回，不采用上游直接返回所选资料全部片段的分支，以维持无证据不生成契约。工程验证与真实效果分别记录于issues。

## 0034 工作台资料事件同步（2026-11-11）

决定：按用户授权以 PostgreSQL 事务通知和单向 SSE 代替前端文档列表定时轮询。通知只使已验证用户的资料缓存失效，实际状态仍经授权 REST 读取。使用 Fetch 流携带 Authorization，重连先同步快照，保留手动刷新与明确的连接状态。

复用 psycopg 和现有线程池等待通知，兼容 Windows 默认事件循环。任务续租不通知，连接关闭释放数据库会话。问答继续一次性返回经证据和引用校验的结果。本轮没有需要双向 WebSocket 的交互。

## 0035 切换向量模型的清空重建（2026-11-12）

按用户要求把历史资料从 `Qwen/Qwen3-Embedding-0.6B` 换成 `BAAI/bge-m3`。全库共用一个向量索引，构建层禁止混用模型，因此先清空旧模型的构建与片段，再按 `ragflow-v1` 重建；版本、原件与发布指针的记录保留，旧片段随构建删除而不原地改写。

重建由 `scripts/rebuild_vectors.py` 执行：默认只统计，`--apply` 建新构建，`--clear-old` 先清空其它模型，`--parser-profile` 供扫描件指定自动路由。原件已丢失的文档先用已发布片段留存正文（`backend/.data/vector-rebuild-backup`），再合成新版本重新入库。词表资源（tiktoken、WordNet、huqie）随仓库放在 `backend/resources/ragflow`，启动器与 `check.py` 自动定位，不再依赖 `.data` 下的准备目录。

## 0036 会话上下文、上下文感知检索与流式问答（2026-11-17）

按用户要求，把单轮、非流式的证据问答升级为会话式问答。参考 QwenPaw v1.1.12.post3 的会话状态与流式任务实现（`app/runner/session.py`、`app/runner/task_tracker.py`、`app/channels/console/channel.py`），只借鉴职责划分与事件下发方式，不引入其 Agent、Skills、Tool Loop、上下文压缩与长期记忆，也不作为依赖。

上下文：复用现有 `conversations`/`messages`，读取当前会话最近 KS_CONTEXT_RECENT_MESSAGES 条（默认 12）作为 Recent Window 进入模型。只保留 user/assistant，按时间正序，剔除窗口尾部与当前问题重复的 user 消息；不做摘要、token 预算、聊天记忆向量化与跨会话记忆。授权沿用 `get_owned`，他人会话与不存在同为 404。

检索：历史进入生成上下文并不能解决检索的主题丢失，因此对含指代/省略线索的问题，把上一轮用户问题拼在原问题前形成独立检索问题；原问题原样保留，不调用模型改写。补全后无候选时只用上文再召回一次。两者都可配置，配置为 0 时退回原问题。

流式：`POST /qa` 的 `stream=true` 返回 text/event-stream，事件为 run_started、context_*、query_rewrite_*、retrieval_*、generation_started、answer_delta、citations、completed、error。生产者线程推进同步栈，事件经 call_soon_threadsafe 投递，客户端断开置停止标记并在检查点退出。

引用：结构化 JSON 无法逐 token 呈现，故流式改用「纯文本 + 段末 `[E#]` 标记」契约，非流式 `/qa` 与 MCP 仍用 JSON sections。两条路径共用同一套引用校验：未知键丢弃并告警，全部段落无有效引用则失败且不写会话。校验发生在流结束之后，`citations`/`completed` 携带校验结果，前端以 `completed.answer` 覆盖临时文本；未通过校验的一轮只发 `error`，临时文本作废。

边界：不实现 Token Budget、Summary Compaction、长期记忆、Agent/ReAct、多 Agent 与 Goal Mode。真实模型下的多轮效果与首字延迟尚未测量，不计入承诺。
